## 4. 요구사항 검증 (Requirement Validation)

### 4.1 검증 기준

| 기준 | 설명 | 검증 방법 |
|-----|------|---------|
| **완전성 (Completeness)** | 모든 이해관계자 요구 포함 | 이해관계자 인터뷰 재검토 |
| **일관성 (Consistency)** | 요구사항 간 모순 없음 | 추적 매트릭스 검토 |
| **검증성 (Verifiability)** | 테스트로 확인 가능 | 테스트 케이스 작성 |
| **명확성 (Clarity)** | 의미 명확하고 모호성 없음 | 기술 검토 회의 |
| **실현성 (Feasibility)** | 기술/일정/예산 내에서 구현 가능 | 기술 리뷰, 규모 추정 |
| **추적성 (Traceability)** | 출처 및 흐름 추적 가능 | 추적 매트릭스 |

### 4.2 검증 활동 계획

```
1차 검증 (Planning 단계 검토)
├─ 이해관계자 회의 (PM, 개발팀, 사용자대표)
├─ 요구사항 명확화 (모호한 항목 정의)
└─ 범위 확정 (포함/제외 범위 합의)

2차 검증 (설계 단계)
├─ 기술 검토 (구현 가능성 재검토)
├─ 성능 계획 (응답시간, 동시접속 기준 타당성)
└─ 보안 검토 (민감정보 보호 방법)

3차 검증 (구현 중)
├─ 단위 테스트 (각 요구사항별 테스트)
├─ 통합 테스트 (요구사항 간 상호작용)
└─ 사용자 승인 테스트 (UAT)

4차 검증 (배포 후)
├─ 프로덕션 모니터링 (KPI 추적)
└─ 만족도 조사 (사용자 피드백)
```
