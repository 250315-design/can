## 1. 기존 비즈니스 프로세스 및 문제점

### 1.1 As-Is 프로세스 (현재 상태)

#### 교내 자원 탐색 프로세스
```
학생/연구자
    ↓
[오프라인 문의 또는 웹 검색]
    ↓
[산발적으로 분산된 정보 수집]
    ├─ 게시판, 이메일, 공지사항
    ├─ 건축학과 자료
    ├─ 교무처 공시 자료
    └─ 보직 교수 연락처
    ↓
[목적지/장비/공간 확인]
    ↓
[직접 이동 또는 다시 문의]
```

#### 자원 관리 프로세스
```
시설팀/교무처
    ↓
[스프레드시트 또는 종이 문서로 관리]
    ↓
[정보 갱신 지연 및 오류 발생]
    ↓
[사용자 문의 급증 → 행정 부담 증가]
```

### 1.2 핵심 문제점 (Pain Points)

| 문제 영역 | 세부 문제점 | 영향 범위 | 심각도 |
|---------|----------|---------|--------|
| **정보 분산** | 자원 정보가 여러 시스템/문서에 흩어져 있음 | 전교 사용자 | ⚠️ 높음 |
| **접근성 저하** | 원하는 공간/장비 탐색에 시간 소요 | 학생, 연구자 | ⚠️ 높음 |
| **실시간성 부재** | 공간 이용 현황 실시간 파악 불가능 | 사용자, 시설팀 | ⚠️ 높음 |
| **네비게이션 한계** | 복잡한 건물 구조에서 길 찾기 어려움 | 신입생, 방문객 | ⚠️ 중간 |
| **자원 활용도 저하** | 유휴 공간 발생, 장비 활용률 불명 | 대학, 시설팀 | ⚠️ 높음 |
| **운영 비효율** | 행정 처리 부담 증가, 중복 관리 | 교무처, 시설팀 | ⚠️ 높음 |
| **데이터 무결성** | 정보 갱신 지연, 오류 축적 | 전체 시스템 | ⚠️ 높음 |

## 2. 기존 시스템 구조 및 평가

### 2.1 현재 구현 상태 (2026-05-20 기준)

#### 아키텍처
```
┌─────────────────────────────────────────────────────────┐
│                    Presentation Layer                    │
│  JSP (campuslogin.jsp, search.jsp, detail.jsp, etc.)    │
│  + Bootstrap 5.3.3 + Bootstrap Icons                    │
└────────────────────────┬────────────────────────────────┘
                         │ JDBC
┌─────────────────────────────────────────────────────────┐
│                  Application/Servlet Layer               │
│  - LoginServlet (hardcoded credentials - DB 미연동)     │
│  - LogoutServlet                                        │
│  - GuestServlet, VisitorServlet                         │
│  - AssetServlet, SearchServlet 등 (미사용 상태)         │
│  - DBUtil.java (공유 연결 헬퍼)                          │
└────────────────────────┬────────────────────────────────┘
                         │ MySQL Driver
┌─────────────────────────────────────────────────────────┐
│                    Data Access Layer                     │
│           MySQL 8.x (campusnav DB)                      │
│  Tables: users, assets, reservations, transfers,         │
│          disposals, professors, prof_subjects, skills    │
└─────────────────────────────────────────────────────────┘
```

#### 배포 환경
- **웹 서버:** Apache Tomcat 9.x
- **데이터베이스:** MySQL 8.x (localhost:3306)
- **접근 URL:** `http://localhost:8080/CampusNav/campuslogin.jsp`
- **개발 환경:** Windows 11 (로컬 개발)

### 2.2 구현 현황 분석

## 3. 사용자 기대사항 및 요청사항

### 3.1 사용자 유형 및 기대

#### 1) 학생 (Student)
- **기대:** 강의실, 스터디룸, 세미나실 빠른 탐색
- **요청:** 위치 기반 필터링, 예약 가능 여부 실시간 확인
- **문제점:** 현재 상세 정보 조회 후 예약하기까지 3-4 클릭 필요

#### 2) 조교 (Assistant)
- **기대:** 자원 상태 모니터링, 예약 승인/거부
- **요청:** 대시보드, 일괄 관리 기능
- **문제점:** 승인 절차 명확하지 않음, 자동화 부재

#### 3) 교수 (Professor)
- **기대:** 연구실, 협력 교수 정보, 장비 상태 확인
- **요청:** 연구 협력자 검색, 장비 예약
- **문제점:** 교수 정보 검색 기능 미약

#### 4) 관리자 (Admin)
- **기대:** 전체 자원 관리, 사용 현황 분석
- **요청:** 자산 추가/수정/삭제, 통계 리포트
- **문제점:** 분석 기능 완전 미구현, 수동 관리만 가능

#### 5) 게스트/외부인 (Guest/Visitor)
- **기대:** 캠퍼스 공개 자원 검색, 방향 안내
- **요청:** 제한된 정보만 조회 가능
- **문제점:** 네비게이션 기능 미작동

## 4. 현재 제약사항 및 가정

### 4.1 기술적 제약사항 (Technical Constraints)

| 제약사항 | 설명 | 영향 |
|---------|------|------|
| **JSP 서버 렌더링만 지원** | 클라이언트 JS 제한적 활용 | 동적 UX 제한, Ajax 기반 기능만 가능 |
| **Servlet 미사용** | 현재 서블릿 코드 미활용 상태 | 아키텍처 혼선, 유지보수 복잡도 증가 |
| **DB 연동 미완료** | LoginServlet 하드코딩 자격증명 | 사용자 등록 불가, 보안 위협 |
| **SQL 준비문 미사용** | 직접 쿼리 구성 → SQL Injection 위험 | 보안 취약점 존재 |
| **프런트엔드 라이브러리 제한** | Bootstrap만 사용 | 고급 UI 컴포넌트 부족 (지도, 차트 등) |
| **로컬 개발 환경만** | 원격 배포 환경 미구성 | CI/CD 파이프라인 없음 |

### 4.2 운영상 제약사항 (Operational Constraints)

| 제약사항 | 설명 | 영향 |
|---------|------|------|
| **Tomcat 로컬 호스트 배포** | 테스트 환경만 구축 | 프로덕션 배포 미준비 |
| **MySQL 로컬 인스턴스** | 개발용 데이터베이스만 구성 | 데이터 백업/복구 전략 없음 |
| **인프라 자동화 부재** | 수동 compile.bat 실행 필요 | 배포 자동화 없음 |
| **모니터링 도구 미구성** | 시스템 상태 모니터링 불가 | 장애 대응 어려움 |
| **성능 최적화 미실행** | 쿼리, 인덱싱, 캐시 전략 없음 | 대규모 사용자 확장 어려움 |

### 4.3 조직적 제약사항 (Organizational Constraints)

| 제약사항 | 설명 | 영향 |
|---------|------|------|
| **팀 규모 4명** | 제한된 개발 리소스 | 병렬 개발 어려움 |
| **교육 기관 특성** | 학기 일정에 따른 변동 | 배포 타이밍 제한 |
| **예산 제약** | 유료 라이선스 도입 불가 | 오픈소스 기술만 사용 |

## 5. 내부 데이터 연계 활용

### 5.1 현재 데이터 연계 현황

```
교무처 시스템
    └─ [미연동] ─┐
                 │
학생 정보 시스템  ├──> [통합 DB]  ──> CampusNav
                 │
시설 관리 시스템  │
    └─ [미연동] ─┘
```

### 5.2 데이터 흐름 (구현된 부분)

#### 로그인 → 역할 결정 → 페이지 렌더링
```
1. campuslogin.jsp (사용자 입력)
2. LoginServlet (자격증명 검사 - 현재 하드코딩)
3. Session 설정 (loginUser, loginName, loginRole)
4. 역할 기반 메인 페이지 리다이렉트
   ├─ student → main_student.jsp
   ├─ assistant → main_assistant.jsp
   ├─ professor → main_professor.jsp
   ├─ admin → main_admin.jsp
   ├─ guest → main_guest.jsp
   └─ visitor → main_visitor.jsp
```

#### 자산 검색 및 조회
```
search.jsp (사용자 검색 조건)
    ↓ JDBC 직접 쿼리
MySQL (assets 테이블)
    ↓ ResultSet 매핑
search.jsp (결과 출력, 페이지네이션 20개)
    ↓ 상세보기 링크
detail.jsp (JDBC로 자산 정보 조회)
    ↓ 이관 이력, 예약 상태 표시
    └─ reserve.jsp 링크
```

#### 예약 프로세스
```
reserve.jsp (예약 입력 폼)
    ├─ AJAX: 중복 예약 검사 (getReservations.jsp)
    └─ POST: 예약 저장 (reserve.jsp 내 INSERT)
        ↓
    MySQL (reservations 테이블)
        ↓
    detail.jsp (예약 상태 실시간 업데이트)
```

### 5.3 데이터 연계 한계

| 항목 | 문제점 | 개선안 |
|-----|--------|--------|
| **외부 시스템 미연동** | 교무처, 시설팀 DB와 독립적 운영 | API 통합 또는 정기 배치 동기화 필요 |
| **수동 데이터 입력** | 자산 8,401개 모두 수동 입력 | 데이터 마이그레이션 도구 개발 |
| **실시간 동기화 부재** | 예약/이관 정보만 실시간 | 변경 이벤트 기반 푸시 필요 |
| **감시 및 로깅 없음** | 데이터 변경 기록 불충분 | Audit trail 테이블 추가 |
| **일관성 검증 부족** | 데이터 무결성 확인 메커니즘 없음 | 정기 데이터 검증 배치 작업 |

## 6. 종합 평가 및 주요 발견사항

### 6.1 강점 (Strengths)

✅ **명확한 기획:** 기획서에 프로젝트 비전과 목표가 명확함  
✅ **기본 기능 구현:** 검색, 예약, 이관 등 핵심 기능 구현 완료  
✅ **역할 기반 접근 제어:** RBAC 구조 적절히 적용  
✅ **데이터 스키마 설계:** 기본적으로 정규화된 DB 설계  
✅ **UI/UX 기본 구현:** Bootstrap 기반 반응형 디자인  

### 6.2 약점 (Weaknesses)

❌ **코드 아키텍처 혼선:** 서블릿/JSP 역할 분담 미흡  
❌ **보안 취약점:** SQL Injection, 하드코딩 자격증명, CSRF 미방어  
❌ **기능 미완료:** AI 추천, 네비게이션, 분석 기능 미구현 (기획서 목표 대비)  
❌ **테스트 및 문서:** 단위 테스트 없음, 설계 문서 미흡  
❌ **성능 최적화:** 쿼리 최적화, 캐싱, 인덱싱 미실행  
❌ **운영 준비:** 모니터링, 백업, 장애 복구 전략 없음  

### 6.3 주요 발견사항

1. **기획-구현 격차 (Planning-Implementation Gap)**
   - 기획서 목표: AI 추천, 실내 네비게이션, 운영 분석
   - 현재 구현: 기본 검색, 예약, 이관만 완료
   - **개선안:** 우선순위 재정의 및 로드맵 수립 필요

2. **아키텍처 혼선 (Architectural Confusion)**
   - 서블릿 코드 존재하지만 미사용 (web.xml 미등록)
   - JSP에 비즈니스 로직 직접 구현 → 유지보수 어려움
   - **개선안:** 서블릿 기반 아키텍처 정리 또는 JSP-MVC 프레임워크 도입

3. **보안 취약점 (Security Risks)**
   - LoginServlet 하드코딩 자격증명
   - JSP에서 동적 SQL 구성 (SQL Injection 위험)
   - CSRF 토큰 미사용
   - **개선안:** 긴급 보안 감사 및 패치 필요

4. **확장성 제한 (Scalability Issues)**
   - GPS/좌표 필드 없음 (네비게이션 구현 불가)
   - 이용자 수, 자산 수 증가에 따른 성능 고려 부재
   - **개선안:** DB 스키마 확장 및 성능 최적화 전략 수립

5. **데이터 무결성 (Data Integrity)**
   - 외부 시스템과 미연동 (수동 데이터 관리)
   - 8,401개 자산 정보 초기 입력 방법 불명
   - **개선안:** 데이터 마이그레이션 도구 개발 및 정기 검증 절차
