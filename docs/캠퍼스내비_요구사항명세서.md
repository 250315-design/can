## 1. 요구사항 정의

### 1.1 기능 요구사항 (Functional Requirements) - 85개

**주요 카테고리:**
- **인증 & 접근 제어 (AUTH):** 7개 - 로그인, 회원가입, 로그아웃, RBAC, 세션 관리
- **자원 검색 & 조회 (SEARCH):** 8개 - 통합 검색, 카테고리/상태 필터링, 페이지네이션
- **자원 상세 조회 (DETAIL):** 8개 - 자산 정보, 예약/이관 이력, 관리자 연락처
- **예약 시스템 (RESERVE):** 9개 - 예약 생성/수정/취소, 중복 방지, 승인, 통계
- **네비게이션 (NAV):** 6개 - 캠퍼스 지도, 실내 네비, 현위치 표시, AR 기반
- **AI 추천 (AI):** 6개 - 사용목적 기반, 유형별, 협력필터링, 인기도, 시간대별, 자연어
- **교수 정보 (PROF):** 6개 - 정보 조회, 담당과목, 기술 태그, 협력 교수, 위치, 메시지
- **자산 관리 (ADMIN):** 9개 - CRUD, 상태 관리, 이관/폐기, 일괄 등록, QR 코드
- **분석 & 대시보드 (ANALYTICS):** 7개 - 대시보드, 이용률, 시간대, 사용자, 리포트

**우선순위 분포:**
- 🔴 P0 (필수): 47개
- 🟡 P1 (중요): 28개  
- 🟢 P2 (선택): 10개

### 1.2 비기능 요구사항 (Non-Functional Requirements) - 37개

| 카테고리 | 요구사항 | 기준 |
|---------|---------|------|
| **성능** | 검색 응답 < 2초, 페이지 로딩 < 3초, 동시 100명 지원 | NFR-PERF |
| **보안** | HTTPS, SQL Injection/XSS/CSRF 방지, 비밀번호 암호화 | NFR-SEC |
| **가용성** | 99% 가용성, 일 1회 자동 백업, RTO 4시간 | NFR-AVAIL |
| **유지보수성** | 코드 커버리지 70%, 단위/통합 테스트, 문서화 | NFR-MAINT |
| **확장성** | 수평 확장, DB 읽기 복제본, 마이크로서비스 구조 | NFR-SCALE |
| **호환성** | Chrome/Firefox/Safari/Edge, 모바일 반응형, WCAG 2.1 AA | NFR-COMPAT |
| **운영성** | 배포 자동화, 모니터링 대시보드, 알림 시스템 | NFR-OPS |

## 2. 요구사항 우선순위 및 범위

### 2.1 Phase별 구현 계획

#### Phase 1: MVP (1개월)
**포함:** 보안 패치, 기본 검색/예약, RBAC, 핵심 기능 안정화  
**제외:** AI 추천, 네비게이션, 분석 대시보드

#### Phase 2: Core Features (3개월)
**포함:** 실내 네비게이션, AI 추천, 관리 기능 확장, 분석 대시보드

#### Phase 3: Enhancement (6개월)
**포함:** 알림 시스템, 교수 협력, 고급 검색, 코드 품질 개선

#### Phase 4: Advanced (12개월+)
**포함:** 자연어 검색, AR 네비, 모바일 앱, 다중 캠퍼스

### 2.2 범위 정의

**포함 (In Scope):**
- ICT 폴리텍대학 캠퍼스 자원 (강의실, 연구실, 장비, 공간)
- 6가지 사용자 역할 (학생, 조교, 교수, 관리자, 게스트, 외부인)
- 웹 기반 플랫폼 (JSP + Java Servlet + MySQL)
- 온프레미스 Tomcat 배포

**제외 (Out of Scope):**
- 모바일 앱 (향후 고려)
- 다국어 지원 (초기 한국어만)
- 클라우드 마이그레이션
- 외부 ERP 연동
- 결제 기능

## 4. 요구사항 변경 관리

### 4.1 변경 요청 프로세스

```
변경 요청 제출 → 영향도 분석 → 승인/거부 → 설계/구현 반영 → 변경 로그 관리
```

### 4.2 영향도 평가 기준

| 영향도 | 기준 | 예시 |
|--------|------|------|
| **낮음** | 단일 기능, 3일 이내 | 검색 필터 추가 |
| **중간** | 다중 기능, 1~2주 | 알림 시스템 추가 |
| **높음** | 아키텍처 변경, 3주 이상 | DB 스키마 변경 |

## 5. 종합 요구사항 요약

### 5.1 핵심 성과 지표 (KPI)

| 항목 | 목표값 | 측정 방법 |
|-----|--------|----------|
| 월 활성 사용자 (MAU) | 2,000명 이상 | 로그 분석 |
| 월 검색 건수 | 10,000건 이상 | 로그 분석 |
| 자원 예약 전환율 | > 20% | 분석 대시보드 |
| 관리자 문의 감소율 | > 30% | 비교 분석 |
| 사용자 만족도 (NPS) | > 50 | 설문 조사 |

### 5.2 예상 효과

```
사용자 만족도 증대
├─ 검색 시간 50% 단축
├─ 예약 프로세스 간편화
└─ 네비게이션으로 방문객 만족도 ↑

운영 효율 개선
├─ 자산 활용률 20% 증대
├─ 행정 부담 30% 감소
├─ 장비 예약 80% 디지털화
└─ 자원 이용 현황 데이터 수집 가능
```
